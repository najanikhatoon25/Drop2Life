# Contributing Guide

Thank you for your interest in contributing to this project! 🎉

We welcome contributions that improve the code, documentation, features, and overall project.

## How to Contribute

### 1. Fork the Repository

Fork this repository to your own GitHub account.

### 2. Clone Your Fork

Clone your fork to your local machine:

```bash
git clone  https://github.com/najanikhatoon25/Drop2Life 
```

Then move into the project directory:

```bash
cd project-name
```

### 3. Create a New Branch

Create a separate branch for your changes:

```bash
git switch -c feature/your-feature-name
```

For a bug fix:

```bash
git switch -c fix/your-bug-name
```

### 4. Make Your Changes

Make your changes while keeping the code clean and readable.

Please:

* Use meaningful variable and function names.
* Keep components and functions focused.
* Follow the existing project structure.
* Avoid unnecessary changes.
* Add or update documentation when needed.

### 5. Test Your Changes

Before creating a Pull Request, make sure the project works correctly.

Run the required commands, for example:

```bash
npm install
npm run dev
```

If the project has tests, run them as well.

### 6. Commit Your Changes

Use a clear commit message:

```bash
git add .
git commit -m "feat: add your feature"
```

Examples:

```text
feat: add search functionality
fix: resolve login validation issue
docs: update README
style: improve button layout
```

### 7. Push Your Branch

Push your changes to your GitHub repository:

```bash
git push origin feature/your-feature-name
```

### 8. Create a Pull Request

Go to the original GitHub repository and create a Pull Request.

In your Pull Request:

* Clearly explain what you changed.
* Explain why the change was needed.
* Mention any related issue.
* Add screenshots when they are useful.

### 9. Review

The project maintainer will review your Pull Request.

You may be asked to make changes before it is merged.

## Reporting Bugs

If you find a bug, please create an Issue and include:

* A clear description of the problem.
* Steps to reproduce it.
* Expected behavior.
* Actual behavior.
* Screenshots or error messages, if available.

## Suggesting Features

Before suggesting a new feature, check whether a similar issue or feature request already exists.

When creating a feature request, explain:

* What the feature is.
* Why it would be useful.
* How you think it could work.

## Code of Conduct

Please follow the project's [Code of Conduct](CODE_OF_CONDUCT.md) when participating in the project.

## Thank You

Thank you for contributing and helping improve this project! ❤️
